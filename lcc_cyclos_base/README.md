# lcc_cyclos_base


Base models and logics using cyclos as transaction provider for numeric local complementary currency
It's part of Lokavaluto Project (https://lokavaluto.fr)

## Installation


Just install lcc_cyclos_base, all dependencies
will be installed by default.

## Configuration 

### Link with Cyclos instance

Define the Cyclos instance to which Odoo must connect in ``Settings/Digital Currency``

Odoo authenticates on the Cyclos REST API with the configured login and
password. Cyclos looks the login up with the default user identification
method of its ``webServices`` channel (``GET /api/auth/data-for-login``
shows it as ``defaultPrincipalType``). If the configured login is of
another kind, set ``Login type for cyclos server`` to the internal name of
that identification method (for instance ``username``): Odoo then sends it
in the ``Principal-Type`` header of every request.

A wrong login type makes Cyclos answer ``401`` with code ``login``, and
Cyclos blocks the IP address of the Odoo server for a while after a few
such failures (code ``remoteAddressBlocked``).

The internal names of the Cyclos objects Odoo uses depend on how the
Cyclos instance was configured. Set them on the currency (the defaults
match the Lokavaluto Cyclos configuration):

- ``Cyclos payment type to credit a user wallet`` / ``... a company
  wallet``: payment types used to credit wallets, as
  ``<system account type>.<transfer type>`` (defaults ``debit.toUser``
  and ``debit.toPro``; ``GET /api/system/payments/data-for-perform``
  lists the available ones).
- ``Cyclos reconversion account type``: system account type receiving
  the reconversion payments (default ``debit``; ``GET
  /api/system/accounts`` lists the system account types).
- ``Cyclos password type of wallets``: password type that Odoo gives a
  temporary value when it creates a wallet user, and that it sets when
  it forces the password of a wallet user (default
  ``-4307382460900696903``; the internal name, e.g. ``login``, also
  works).

### Cyclos group of new wallets

The ``Cyclos groups of new wallets`` rules of the currency choose the
Cyclos group in which Odoo creates the user of a new wallet. Each rule
has a priority, a domain on the holder (the contact of the wallet) and
the internal name of a Cyclos group (``GET
/api/users/groups-for-registration`` lists the available ones). Odoo
uses the first active rule, by priority, whose domain matches the
holder; it refuses to create the wallet when no rule matches. For
instance:

- priority 5, holders ``[('category_id.name', '=', 'Association')]``:
  group ``associations``;
- priority 10, holders ``[('is_company', '=', False)]``: group
  ``individual``;
- priority 20, holders ``[('is_company', '=', True)]``: group
  ``professional``.

Rules only apply when Odoo creates a Cyclos user: changing them moves
no existing user. Only administrators edit them. The ``Preview the group
of a holder`` button of the currency shows which rule and group a
contact would get, without creating anything.

Updating the module to version 16.0.1.5.0 replaces the former ``Cyclos
group of person wallets`` / ``... company wallets`` settings of each
Cyclos currency by two rules, ``Persons`` and ``Companies``, giving the
same groups.

### Fields of Cyclos users

The ``Cyclos user fields`` tab of the currency lists fields of the Cyclos
users that Odoo computes from their wallet (``res.partner.backend``):
each line gives a Cyclos field and a value. Odoo sends them when it
creates the Cyclos user, and when the ``Synchronize to Cyclos`` button of
a wallet, or ``Synchronize all Cyclos users`` of the currency, is used.

- **Cyclos field**: ``name``, ``username``, ``email`` (fields of the
  Cyclos user itself), or the internal name of a custom field
  (``GET /api/users/{user}/data-for-edit`` lists them).
- **Value**: the name of a field of the wallet (``cyclos_login``), or a
  Python expression where the fields of the wallet are names and
  ``record`` is the wallet (``partner_id.city``,
  ``partner_id.create_date.date()``, ``"constant"``). A value starting
  with ``=`` is always an expression. Expressions run in Odoo's sandbox
  and can only read fields: methods of records are refused.
- The result is sent as text: an empty field gives an empty value (which
  empties the Cyclos field), booleans give ``true`` / ``false``, dates
  their ISO form. A Cyclos field that is not listed is left as it is.

When updating a user, Odoo reads its current fields from Cyclos and
sends them back with the computed ones. Cyclos silently ignores a field
its permissions do not let Odoo's account set, so Odoo refuses to send
such a mapping, naming the fields (``profileFieldActions`` of
``data-for-new`` when creating, of ``data-for-edit`` when updating): a
field may be settable at creation only. Cyclos may also refuse changes:
``username`` is the member's login (generated by some Cyclos instances),
``email`` may be required or need a validation by the member, a required
custom field cannot be emptied, and a choice field expects the internal
name of one of its values. Addresses, phones and images cannot be set
this way. When synchronizing all users, a refused user gets the error in
its wallet history and the others are still updated.

### Creating Cyclos wallets from Odoo

Cyclos sends no e-mail when Odoo creates a wallet user, and the member
never receives a password by e-mail:

1. Odoo creates the Cyclos user with a random password of 32 letters
   and digits, marked as to be changed, and asks Cyclos to skip its
   activation e-mail. Odoo keeps that temporary password on the wallet,
   readable by administrators only, and stores the login Cyclos returns
   (Cyclos may generate it) as ``Cyclos login``.
2. Odoo e-mails the member (template "Cyclos wallet: set your password")
   their login and a link to Odoo (``/cyclos/set-password/<token>``).
3. When the member follows the link, Odoo opens a session of the member
   in Cyclos with the temporary password, on the channel of the Cyclos
   web interface (``main``), and redirects the member to that interface
   (``Cyclos web address`` of the currency) with this session. Cyclos
   asks the member for their new password only: no code, no old
   password. The password the member chooses never passes through Odoo.
4. Odoo forgets the temporary password only once Cyclos reports the
   member's password as ``active``: when the link is followed again, and
   every hour (scheduled action "Wallet: forget Cyclos temporary
   passwords replaced by holders"). Until then the link keeps working;
   afterwards, it leads to the Cyclos login page.

The ``Send password setup e-mail`` button of the wallet sends a new link,
which replaces the previous one, as long as the member has not chosen
their password. Odoo refuses to create a wallet while the currency has
no ``Cyclos web address``, or for a partner without an e-mail address.

After choosing their password, the member stays on the Cyclos home
page. To send them on to Odoo instead, set ``Cyclos page after the
password is chosen`` on the currency to the internal name of a Cyclos
content page that redirects to Odoo: Odoo adds
``returnTo=page-content!page=<internal name>`` to the link, and Cyclos
opens that page once the password is chosen. Cyclos only accepts its own
pages there, and Odoo cannot create the page through the Cyclos API: a
Cyclos administrator creates it once, in Content > Menu and pages, for
the configuration of the member groups:

- add a menu item of type "Content page", with an internal name (for
  instance ``odooRedirect``);
- as content, in source mode, HTML such as the following, where
  ``odoo.example.org`` is the address of Odoo (Cyclos ignores
  ``<script>`` and ``<meta http-equiv="refresh">``, but runs the
  ``onerror`` attribute of an image):

    ```html
    <p>Redirecting to your account…</p>
    <img src="/nonexistent.png" onerror="window.location='https://odoo.example.org/my/home'">
    <p><a href="https://odoo.example.org/my/home">Continue</a></p>
    ```

The Cyclos instance must:

- give the channel of its web interface (``main``, "Main web" /
  "Site web principal") an access password: the login password type.
  Odoo opens the member's session on that channel;
- give the registration groups an initial status that lets their users
  log in (``active``);
- accept the temporary password: the password type must allow at least
  32 characters.

Odoo needs no Cyclos e-mail, so the Cyclos server's ability to send
e-mails does not matter for this.

### OAuth Configuration

Source: [Cyclos OAuth wiki page](https://wiki.cyclos.org/index.php/OpenID_Connect_-_OAuth2)

All url should be with `https://` in front.

Follow instruction to:

- Enable channel as a valid way to users to authenticate
- Create a client configuration (Users / OAuth Client)

  - name: as you want, no real use.
  - Client id: can choose anything
  - Permissions OpenID Connect, Basic profile information
  - Read e-mail address
  - return url: (probably don't need all of them)

    ```
    https://${ODOO_URL}/my/home
    https://${ODOO_URL}/auth_oauth/signin
    https://${ODOO_URL}/my/web
    ```

In _odoo_: General Settings, search for 'OAuth providers'. Create one with:

- Same client-id then the one used in Cyclos
- scope: "openid profile email" (space separated). Odoo first looks for
  the Cyclos wallet (``res.partner.backend``) whose Cyclos id is the
  logged-in Cyclos user: its partner's user is used, or created on that
  partner. Without such a wallet, Odoo needs the e-mail to reconcile the
  login with an existing ``res.users`` (or create a new one) and to create
  the ``res.partner.backend``. Cyclos only returns the e-mail in the
  ``userinfo`` response when the ``email`` scope is requested AND the
  e-mail is enabled in the "My profile fields" of the user's product.
- auth: ``${CYCLOS_URL}/api/oidc/authorize``
- validation: ``${CYCLOS_URL}/api/oidc/token``
- data: ``${CYCLOS_URL}/api/oidc/userinfo``

Only the client id will be used

A member (portal user) who logs in with Cyclos lands on their portal home
(``/my/home``), where Odoo would otherwise send them to the website home
page. A page explicitly asked for (``/web/login?redirect=...``) is kept.

Note: You must install `lcc_cyclos_base` module that corrects OAuth
implementation in odoo.
